# Wrenfield Value Workshop Output

> This is a fictional example. Wrenfield, the people and the figures are invented.

## The Work Today

Wrenfield Insurance Group is a large commercial insurer. After a claims call, claims handlers draft a summary letter to the policyholder and update the claims system with a coverage decision and next steps. Priya Ahluwalia, Head of Claims Operations, says handlers spend a significant part of each day on this drafting, and new handlers take months to write letters that pass a compliance review first time.

The group agreed the problem is real and specific. It did not agree on how large the effect is, since no one had measured drafting time separately from the rest of a handler's day.

## Why It Matters

- Claims handlers repeat the same drafting structure for every letter, which slows a queue that is already tracked against a regulatory turnaround time.
- New handlers are coached individually on letter writing, which does not scale as the team grows.
- Compliance already reviews every letter before it is sent, so a drafting error is caught, but only after the handler's time has already been spent.

## Better Looks Like

Wrenfield described a useful improvement as:

1. a claims handler can prepare a first draft of the letter and the coverage decision from the call notes and policy documents already in the claims system;
2. the handler remains responsible for checking, editing and sending it, exactly as today; and
3. compliance still reviews every letter before it goes out, with no change to that step.

The proposed measure was time spent drafting a sample of letters, compared before and after. No baseline exists yet.

## First Test

Not proposed. Wrenfield's claims correspondence and policy documents are classified as sensitive customer data under its own information security policy. Using any AI tool against that data, even for a small sample, requires sign-off from Information Security and a review through Wrenfield's approved-vendor process in Procurement. Neither had started. Proposing a test now would assume an approval that does not exist, which the [Value Evidence Check](../methods/value-evidence-check.md)'s Decision row rules out directly.

## Decision

Wrenfield agreed to raise the request with Information Security and Procurement first, using the problem and measure defined in this workshop as the business justification. No test, tool or data access was agreed. This is an honest "not yet," for a different reason than a workshop that cannot name an owner: here the owner, problem and measure are all clear, and the gate is an approval process that has not been started.

## What Remains Unknown

- Whether Information Security would approve any AI tool for this data class, and on what terms
- How long the approved-vendor review would take once started
- Whether a smaller, less sensitive sample of data exists that could be tested sooner without waiting for full approval
- Whether the time saving would still be worth the compliance overhead once a tool is approved
